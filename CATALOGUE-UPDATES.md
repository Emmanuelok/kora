# KORA catalogue update workflow

A daily ChatGPT task, KORA Catalogue Updates, checks releases and can publish validated changes to this private Site. It is a scheduled research/publication task, not a direct real-time manufacturer API. The task was activated 24 September 2026. Preserve the current audience.

1. Open latest Sites source with site-workflow before editing. Read data/brand-watch.json. Its 193+ brand discovery queries include all branded catalogue entries; officialSources are populated only when verified. Discover official sites for remaining brands, never infer a domain and mark it verified. Check brand announcements and relevant new brands across all29 departments. Record per-brand successful check timestamps and failures; do not claim exhaustive completion after partial searches.
2. Only include publicly announced, identifiable real products. Obtain exact manufacturer images and specifications from official pages. Record full source URL, imageSource, checked date, model/configuration, announcement/release dates and coming_soon/released status. Rumours and placeholders are excluded. Release does not mean local stock. Future releases can be saved/requested but no payment/preorder claim is made.
3. Normalize verified candidate JSON to Product schema. `node scripts/upsert-catalogue.mjs /path/to/verified-candidates.json` validates mandatory evidence fields and upserts stable IDs. The script does not itself verify claims on websites: the scheduled researcher must do that. Avoid duplicate records for the same SKU/configuration; distinct local retailer configurations are explicitly labeled.
4. `node scripts/refresh-prices.mjs` rechecks exact Shopify retailer variant IDs from approved local hosts. Never substitute a different variant, a deposit, or foreign currency conversion. A large price change/model mismatch needs source review. Failures retain previous evidence, never refresh its checked date. Prices older than14 days automatically display Price on request. For additional retailers verify Ghana currency, model, storage/RAM, SIM, condition, bundle and applicable color. Local reference is not a KORA stock/offer claim.
5. Reconcile past release dates using a current official source, not the calendar alone. Download verified product images to public/images/products with their imageSource retained. Verify image bytes and visible subject. Do not replace unavailable images with another product or generated product appearance.
6. Update data/update-status.json honestly: last successful check, registry size, releaseCount, priceCount and concise history. Record failures. Keep status timestamps truthful. Rebuild public/catalogue-inventory.csv with `node scripts/export-catalogue.mjs`.
7. Run `node node_modules/typescript/bin/tsc --noEmit`, `node scripts/verify-store.mjs` and the Sites production build. Check changed image/link destinations and checkout math. Publish using Sites workflow from the exact pushed source, respecting existing audience. Retain old source on failed validation.
8. Notify only on meaningful catalogue/price changes or failed checks. No customer emails, payments, stock writes, new supplier contracts or audience changes are authorized by this task.

Data contracts: data/products.json is authoritative catalogue; data/release-sources.json stores this update's manufacturer research; data/brand-watch.json tracks discovery coverage; sourcePriceCheckedAt is original-market evidence date; priceCheckedAt is Ghana exact-variant price date. Cart/request prices are recalculated on the server, nullable when no verified Ghana reference exists. Quote totals exclude unpriced lines explicitly.

## Product galleries

Every product requires at least **five distinct photographs of its exact model/configuration**. The current import is incomplete: read `data/gallery-coverage.json` and `data/gallery-evidence.json` for coverage and explicit access failures. `productsWithFiveOrMoreImages`, `productsAwaitingFiveImages` and `minimumAdditionalImagesRequired` track this requirement. `complete` is true only when every product reaches five. Do not claim every product is complete while source gaps remain.

- Keep stable catalogue IDs and merge accepted photo records into `data/product-galleries.json`. Each entry has `url`, optional `thumbnail`, `caption`, `sourceUrl` and `checkedAt`. Preserve existing accepted views. Do not copy a different colour, size, generation, bundle, accessory-only picture or duplicate crop to increase the count. Retain the existing cover when no additional correct photo is verified.
- For new releases, collect the official product gallery while verifying the product. Use exact URLs exposed by the source; validate image response bytes, dimensions and visible subject. Record evidence in `data/gallery-image-validation.json`. Verify additional retailer views against exact model/configuration.
- Import reviewed batches with `node scripts/import-galleries.mjs /path/to/verified-gallery-batch.json`. The batch contains `checkedAt`, an ID-keyed `galleries` map, a `validation` array and optional ID-keyed `evidence`. Each photo needs successful image-byte validation, dimensions and hashes. The importer preserves the order of existing accepted views and appends distinct reviewed additions, including upgrades to galleries that already have two to four photos. It rejects unknown IDs, duplicate URLs/pixels within the submitted batch and missing evidence; existing duplicates are skipped rather than counted twice. Visual/configuration review must finish before import; passing HTTP checks alone is insufficient.
- `python scripts/review-gallery-upgrades.py --output /tmp/kora-gallery-review --limit 25` prepares candidate contact sheets from exact-SKU image arrays already retained in `data/gallery-source-review.json`. It does not infer filenames or publish. Review every accepted view for model, color, bundle, duplicate crops and product-free graphics, and record the accepted source indices before building an import batch. The script requires Pillow and stops on HTTP 403/429.
- The Best Buy product API denied access during the initial collection. Do not bypass blocks, rotate identities, guess filenames, or retry a denied source repeatedly. A future scheduled check may make one normal low-rate access attempt; stop immediately on HTTP 403/429 and retain existing records and dates. `python scripts/collect-product-galleries.py` collects at most 25 candidates at one worker by default, resumes from the checkpoint, and writes only under ignored `work/`. It does not verify all visual/configuration claims or publish. Review its candidate output before importing; never mark blocked/unrequested items checked successfully.
- Update the coverage totals, evidence and `data/update-status.json` gallery history. Rebuild the downloadable inventory and gap list with `node scripts/export-catalogue.mjs`; run `node scripts/verify-galleries.mjs` alongside the other required checks. Only publish validated source using the existing Sites workflow and private audience. A source gap does not justify invented photography.
- The export also regenerates `data/gallery-previews.json` for accurate storefront photo counts and alternate views. The downloadable gap CSV includes every product below five photos, its verified count and its missing-photo count. Leave unrequested products pending, distinguish a source error from an exact-configuration gap, and record a bounded source attempt truthfully rather than claiming every product was checked.
- If an existing cover is demonstrably a different configuration, withhold it: set `imageVerificationStatus` to `under_review`, record `imageVerificationNote`, and use the labelled `/images/photo-under-review.svg` notice. The gallery API returns no images for held records. Clear the hold and replace the notice only after the exact product photography is verified; preserve the original source evidence in `data/gallery-source-review.json`.
